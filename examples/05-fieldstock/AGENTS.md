# FieldStock project instructions

Read [the local selected profile](docs/stack/AGENTS.md) and follow its task-to-reference routing before affected work. Read the relevant entries in [the authoritative decision record](docs/stack-decisions.md) for scope, open choices, commands and verification state. Applicable performance-first defaults remain the baseline; explicit user choices and recorded project decisions refine them. Ordinary feature requests do not authorize wholesale replacement. A decision describes choices, not permission for migrations, external mutations, deployment or broader development.

When work reaches a deferred decision's trigger or blocked scope, ask its recorded question before dependent implementation; continue independent authorized work. Keep accepted choices during unrelated work. Reopen only the affected boundary when requirements change or evidence warrants it. Update the existing decision ID and setup state in the single record.

This foundation contains only a SolidStart web shell and public Rust health API. Do not choose/connect persistence, introduce domain schema/migrations or stock writes before D-003 is resolved. Do not claim private data or stock mutations are authorized before D-004 is resolved. Health means process response only.

Prefer Bun over pnpm over npm; rootless Podman over Docker; uv for Python. Keep build concurrency at two jobs where supported. Never terminate T3 Code or unrelated processes, change shared runtimes, or exhaust host resources. Stop task-owned services after verification. Remote provisioning, publishing, paid services and production migrations are outside current authorization. Never commit credentials or put them in browser code.

Keep the local profile snapshot intact unless a scoped policy update is authorized. Copying unused references selects no optional technology. No additional agents are needed for this initial setup.
