# Kickoff evaluation rubric

Record the original agent output and independent results before any evaluator repair. Each category is scored 0–4: 0 absent/incorrect; 1 substantial gaps; 2 useful but incomplete; 3 solid with a minor limitation; 4 complete for the authorized foundation and available environment.

| Category | What earns credit |
| --- | --- |
| Selection and scope | Appropriate profile branch/defaults, justified departures, required components, no speculative architecture |
| Installation and reproducibility | Supported compatible pinned tools, one manager/lock, frozen/locked verification, runnable commands and prerequisite documentation |
| Runtime and behavior | Separate type checks, actual build/artifact startup, relevant browser/interaction/service checks, no false passing results |
| Continuity and deferred choices | Portable selected policy snapshot, concise active routing, preserved existing rules, one usable decision record, actionable unresolved triggers |
| Reliability and delivery | Valid configuration/secret boundaries, bounded resources, failure behavior where implemented, honest limits, local commit/clean state and service lifecycle |

Convert the total out of 20 to a score out of 10. Missing external access is not itself a failure when accurately documented and independent setup is complete; missing checks or false readiness claims are. An appropriate minimal foundation should not be penalized for future features intentionally outside scope. UI evaluation is limited to the requested initial surface, not completion of the imagined product.

Report separate readiness verdicts, check results, overhead/architecture findings and attribution: skill-specific wording/decisions observed in traces versus general model/environment behavior. Five assisted runs with no control group can show compliance and gaps, not quantify causal improvement over no skill. Prepared answers do not validate a live interview. Keep baseline findings distinct from later repairs.
